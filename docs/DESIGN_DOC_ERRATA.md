# Group 11 Design Document Errata (`docs/DESIGN_DOC_ERRATA.md`)

This document records known discrepancies between the **Group 11 Design Document (v0.1, 05 Oct 2026)** and the authoritative Round 2 implementation in this repository. In every case below, the code implements the networking-sound behaviour and does **not** copy errors from the v0.1 draft.

---

| # | Design Document Section & Claim | Why the v0.1 Statement is Flawed | What the Implementation Actually Does |
| :- | :--- | :--- | :--- |
| **1** | **Section 3.3 (Gap Recovery):** *"The recovery server resends the missing messages over the UDP connection."* | Resending recovery replies over unacknowledged UDP multicast would broadcast unicast repair traffic to all subscribers and offer no delivery guarantee or flow control for large gap replays. | Recovery requests and responses use a dedicated, framed **TCP connection** (`RecoveryTcpServer` / `RecoveryTcpClient`, default port `9090`), with chunked streaming (`RECOVERY_CHUNK` + `RECOVERY_COMPLETE`) for replays exceeding 1 MiB. |
| **2** | **Section 3.5 (Snapshots):** *"Periodic snapshots are taken per instrument with a per-instrument sequence number."* | The multicast feed uses a **single global monotonically increasing sequence number** across all instruments (`AAPL`, `GOOGL`, `AMZN`, `NFLX`, `META`). A single-instrument snapshot cannot safely advance a subscriber's global `expected_sequence_` without corrupting other instruments' books. | `SnapshotManager` creates **composite multi-instrument checkpoints** (`instrument_id = 0` in the snapshot header, with per-level `instrument_id` inside each `SnapshotPriceLevel`) keyed by the global sequence number, and supports `--snapshot-on-demand` so any `TOO_OLD` gap can be resolved immediately. |
| **3** | **Section 3.6 (Fairness Metric):** *"Fairness between FCFS and Round-Robin is evaluated using Jain's fairness index on total requests served per subscriber."* | When Subscriber 1 experiences 50% packet loss and Subscribers 2–7 experience 2% packet loss, Subscriber 1 submits ~25x more requests. At the end of a quiescent run where all requests are served, every scheduler policy serves the exact same number of requests per subscriber, yielding the same raw-count Jain index (~`0.305`), which measures **demand imbalance** rather than scheduling fairness. | The system reports: (1) **per-subscriber queue-wait percentiles (`p50`, `p95`, `p99`, `max`)** in `recovery-requests.csv` and `EXCHANGE_RESULT`, (2) **quiet-subscriber vs noisy-subscriber `p95`/`p99` recovery latency**, and (3) **saturated-window Jain's fairness index** (`recovery_saturated_fairness_jain_ppm`) computed strictly over epochs where `queue_depth_at_enqueue >= 2`. |
| **4** | **Section 3.2 (Initial Sequence):** *"The subscriber initializes its expected sequence number from the first packet received."* | If sequence `1..5` are dropped and the first packet to arrive is sequence `6`, initializing `expected_sequence = 6` silently loses the head of the stream (`1..5`). | `SequenceTracker` initializes `expected_sequence_ = 1`. Any first arrival with `sequence > 1` immediately records a missing head range `[1, seq - 1]`. |
| **5** | **Section 3.5 (Snapshot Integrity):** *"Checkpoints are hashed using FNV-1a."* | FNV-1a is a non-cryptographic 64-bit hash with trivial collision/tamper properties. | `SnapshotHasher` computes a **256-bit cryptographic SHA-256 hash chain** (`hash = SHA256(sequence || instrument_id || timestamp_ns || previous_hash || canonical_levels)`), and `BookBuilder::digest()` uses the same canonical SHA-256 digest to verify that the subscriber's final reconstructed order book matches the exchange's published order book at sequence $L$. |
| **6** | **Section 3.8 (Recovery Latency):** *"Recovery latency is the round-trip time of the TCP recovery request."* | Measuring only TCP RTT omits the `gap_grace_ms` wait, worker queueing, and events repaired by the second multicast feed (`Feed B`). | `DualFeedSubscriber` timestamps every missing sequence at the instant the gap is first detected ($t_{\text{gap}}$) and records per-missing-event latency ($t_{\text{deliv}} - t_{\text{gap}}$) separated by class (`other_feed`, `tcp_recovery`, `snapshot`), plus a separate `tcp_request_rtt` timer. |
